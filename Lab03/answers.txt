Part 2: Analyze Selection sort

a. At a high level, what is the approach that selection sort takes to sort the items of the
list? (i.e., why is it called selection sort?)

At a high level, selection sort approach is implemented by going through the list and selecting the smallest value from 
the unsorted part of the list. 
Next it swaps the smalles value into the correct position, and keeps doing this until the whole list is sorted. 




b. What is the time complexity (i.e., runtime) of selection sort (Big O notation)? How
can you tell just by looking at the code?

The time complexity of selection sort is 0(n^2). 
I am able to tell by looking at the code as there is a loop inside another loop. 
The outer loop goes through the array, and for each value of i, the inner loop searches through the rest of the array to find the smallest value. 
Since the algorithm compares many pairs of values, the runtine grows quadraticaly as the list gets bigger.

The space complexity of selection sort is 0(1). 
It sorts the array by changig the original array instead of making a new one; array in-place. 
It only uses a few extra variables like n, i, j, and min_idx, so the amount of extra memory doesn't grow with the size of the list.

Part 4: Analyze and Implement Bubble Sort

a. At a high level, what is the approach that bubble sort takes to sort the items of the list? Why is it called bubble sort?

Bubble sort works by comparing two neighboring items at a time. If the item on the left is bigger than the item on the right, they get swapped. 
This keeps happening until the larger values move toward the end of the list. 
It is called bubble sort because the biggest values “bubble up” to the end of the list after each pass.



b. What is the time complexity of bubble sort? How can you tell just by looking at the pseudocode?

The time complexity of bubble sort is O(n^2). 
I can tell because there is a loop inside another loop.
The outer loop goes through the array, and the inner loop compares neighboring values.
Since the algorithm may need to compare many pairs of values, the runtime grows quadratically as the list gets bigger.


c. What is the space complexity (i.e., additional storage usage) of bubble sort (Big O notation)? How can you tell just by looking at the pseudocode?

The space complexity of bubble sort is O(1). 
It sorts the original list in-place and does not make a new list.
It only uses a few extra variables (i and j), so the extra memory does not grow with the size of the list.

def bubble_sort(A):
    n = len(A)

    for i in range(n - 1):
        for j in range(n - 1 - i):
            if A[j] > A[j + 1]:
                A[j], A[j + 1] = A[j + 1], A[j]

Even though selection sort, insertion sort, and bubble sort all have O(n^2) time complexity, they do not all run at the exact same speed. 
Big O shows how the runtime grows as the input size gets bigger, but it does not show constant factors or small differences in how the algorithms are written. 
Based on the runtimes, the algorithms all get much slower when the list size increases, especially from 1,000 to 10,000 items. 
This makes sense because O(n^2) algorithms grow very quickly. 
Bubble sort is usually slower because it does a lot of repeated neighboring comparisons and swaps.
